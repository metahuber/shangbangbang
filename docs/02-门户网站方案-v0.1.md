## 〇、先说一个结论

门户网站**不是公司宣传页**，它是你的**销售转化工具**。

它存在的唯一核心指标：**留资数**（加微信 / 留电话 / 提交需求）。

所有设计决策服从这一条 —— 首页好不好看是次要的，能不能让老板留下联系方式才是主要的。

同时它要干成三件事：

1. 让工厂 / 商铺老板 **30 秒内明白**「你能解决我什么问题」
2. 让他相信**你能做成**（案例、交付物、服务承诺）
3. 让他**立刻能联系到你**

## 二、目标客户与转化路径

| 客户 | 他现在的痛点 | 他的决策特点 | 打动他的东西 |
|---|---|---|---|
| 外贸工厂老板 | 只有阿里国际站 / 中国制造网，没有自己的官网，客户没法给他背书 | 看同行、看案例、怕没人管 | 同行案例、询盘数据、"我们帮你运营" |
| 本地商铺老板 | 被平台抽佣，想做自己的客户池 | 决策快、怕复杂、要人教 | 便宜的起步价、"你不用懂技术" |
| 连锁 / 品牌方 | 多门店管理混乱 | 要试用、要对接 | 系统能力、数据看板 |

**转化路径**（每一环都要有出口，别指望用户自己去找"联系我们"）：

```
搜索/推荐进入
   → 首页（30 秒看懂你是谁）
   → 解决方案页（我是外贸工厂 / 我是本地商铺 → 对上号）
   → 产品详情（功能 + 价格 + 交付物）
   → 案例 / 信任背书
   → 留资 / 加微信  ← 每页都必须有这个按钮
```

## 三、栏目结构（Sitemap）

| 层级 | 栏目 | 作用 | 优先级 |
|---|---|---|---|
| L1 | **首页** | 30 秒讲清你是谁、能干什么 | P0 |
| L1 | **产品**（下拉：外贸网站 / 小程序 / AI 工具 / 内容服务） | 产品总览 + 各产品详情 | P0 |
| L1 | **解决方案**（外贸工厂 / 本地商铺 / 连锁门店 / 产业带） | 按客户类型重组内容，转化率远高于纯产品列表 | P0 |
| L1 | **客户案例** | 信任的核心来源 | P0 |
| L1 | **价格** | 过滤无效咨询、提高有效转化 | P0 |
| L1 | **联系我们** | 表单 + 微信 + 电话 | P0 |
| L1 | 关于我们 | 公司 / 团队 / 服务承诺 | P1 |
| L2 | 服务流程与交付物 | 降低"钱花在哪"的不确定感 | P1 |
| L2 | 常见问题 | 减少售前沟通成本 | P1 |
| L2 | 行业知识库 | SEO 长期自然流量 | P2 |

**为什么必须有「解决方案」而不只是「产品」**：老板不搜"多语言建站"，他搜"工厂怎么做外贸网站"。先对上人，再讲产品。

## 四、首页逐屏文案框架（拿去直接改，不用从零写）

| 屏 | 内容 | 要点 |
|---|---|---|
| 1. 首屏 Hero | 主标题 / 副标题 / 双 CTA / 右侧真实界面截图 | 主标题讲结果不讲技术；CTA = 「免费获取方案」+「看客户案例」 |
| 2. 信任条 | 已服务 X 家工厂与商铺 · X 个外贸站点 · 平均 X 天交付 | 数字可以少，但不能没有 |
| 3. 痛点共鸣 | 三张卡：没有官网只能靠平台 / 有网站却没询盘 / 有客户但留不下来 | 让他点头"说的就是我" |
| 4. 产品矩阵 | 6–8 个产品卡，点击进详情 | 一屏看完你的能力边界 |
| 5. 解决方案入口 | 我是外贸工厂 / 我是本地商铺 / 我是连锁品牌 | 分流，提高后续页转化 |
| 6. 交付物与流程 | 4–5 步，每步产出什么 | 老板最怕"交了钱不知道你在干嘛" |
| 7. 客户案例 | 3 个，带数据（上线周期、询盘量） | 新公司可用"样板案例" |
| 8. 价格档位 | 3 档 + 定制咨询 | 明码标价反而提高转化 |
| 9. 为什么选商帮帮 | 对比表：自己招人 / 找外包 / 只做平台 / 商帮帮 | 直接给决策理由 |
| 10. 常见问题 | 6–8 条 | 售前问题前置 |
| 11. 底部 CTA | 表单 + 微信二维码 + 电话 | 页面再长，末尾也要有出口 |

## 五、产品内容怎么组织（**决定网站能不能长大**）

**不要把产品写死在页面里。** 用数据驱动：

```
产品数据（JSON / 数据库）
  ├ slug          例：foreign-trade-website
  ├ 名称          通用版外贸网站
  ├ 一句话卖点
  ├ 适用客户
  ├ 功能列表
  ├ 交付物
  ├ 价格档位
  ├ 相关案例
  ├ FAQ
  ├ 封面图 / 排序 / 上下架状态
        ↓
   一个模板页渲染所有产品
```

以后**加产品 = 加一条数据，不用改代码**。

> 顺带一个关键判断：这套「产品数据 + 模板渲染」的结构，**就是你后面通用版外贸站的雏形**。
> 门户就是你自研建站引擎的第一个客户 —— 吃自己的狗粮，这一步不浪费。

## 六、技术选型

| 方案 | 优势 | 劣势 | 适合谁 |
|---|---|---|---|
| **A. Next.js + TypeScript + Tailwind**（推荐） | SEO 与性能好；组件和后端能力可直接复用到外贸站与后台 | 需要熟悉 React | 后面要自研 SaaS（你的情况） |
| B. Astro + Tailwind | 纯内容站最快最轻，Lighthouse 满分 | 后期要做后台 / SaaS 得换栈 | 只想先上线一个站 |
| C. WordPress | 上线最快、插件生态大 | 与后续自研产品线是两套技术栈，长期维护累 | 不打算自研 SaaS |
| D. Nuxt + Vue | 同 A | 视你熟悉 Vue 还是 React | 熟悉 Vue |

**唯一原则：门户的技术栈必须和后面通用版外贸站一致，否则这一个月等于白干。**

选 A 还是 D，只取决于你熟 React 还是 Vue —— 见第十一节问题 1。

## 七、SEO（门户自己必须先做好，否则连"给客户演示"都做不到）

- 每页独立 TDK、语义化 HTML、`sitemap.xml`、`robots.txt`
- 结构化数据：Organization / Product / FAQ / Breadcrumb
- 内链：产品 ↔ 解决方案 ↔ 案例 互相串联
- 性能：静态化 + WebP 图片 + CDN
- 目标关键词（示例）：外贸网站建设、工厂外贸官网、外贸独立站、商铺小程序开发、门店小程序制作
- 长期：行业知识库持续更新（P2）

## 九、风险与应对

| 风险 | 说明 | 应对 |
|---|---|---|
| **品牌 / 商标** | 查到有「杭州商帮帮信息技术有限公司」，需确认商标是否已被占用 | 中国商标网自查；重点看 **35 类（广告销售）与 42 类（软件服务）**；必要时先提交注册 |
| **备案** | 国内服务器必须备案，需企业主体与法人信息 | 尽早启动，别等开发完才办 |
| **内容写不出来** | 门户最怕产品页空着 —— 这是 90% 建站项目烂尾的原因 | 我先给你每页**文案草稿**，你只负责改，不从零写 |
| **没有案例** | 新公司没有真实客户案例 | 用产品样板案例 + 服务承诺 + 界面实拍替代，并尽快积累第一批 |
| **功能蔓延** | 门户越做越大，变成半年工程 | 严格按 P0 上线，P1/P2 迭代 |
