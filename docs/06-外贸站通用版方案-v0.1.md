## 〇、先说三个必须先定的战略问题

这三条决定架构，定错了后期极难改（比选 React 还是 Vue 重要得多）。

### 1️⃣ 服务器放海外，而不是国内 —— 这条价值最大

| | 国内服务器 | **海外服务器（建议）** |
|---|---|---|
| ICP 备案 | **每个客户域名都要单独备案** | 通常不需要（备案要求针对境内服务器） |
| 交付周期 | 3–15 天 + **备案 5–20 工作日** | **真的 3–15 天** |
| 你的目标客户（海外买家）访问速度 | 慢，要靠 CDN 补 | 快 |
| 老板在国内访问后台 | 快 | 稍慢（香港节点可接受） |

**这一条决定了你的生意能不能成立。** 你门户上写着"3–15 天交付"——如果服务器在国内，每个客户都要等备案，这个承诺就是假的。外贸站面向的是**海外客户**，服务器放海外是行业普遍做法。

> ⚠️ 具体要求建议向服务器服务商和代办确认；如果客户坚持要国内节点，那就是另一个交付周期（+备案），报价要体现出来。

### 2️⃣ 交付模式：单实例多站点（不是每个客户装一套）

```
❌ 每客户一套部署              ✅ 一套系统，N 个站点
   客户 A → 服务器 A              客户 A ┐
   客户 B → 服务器 B              客户 B ├→ 同一套系统
   客户 C → 服务器 C              客户 C ┘   （按域名区分）
   每套都要升级、备份、修 bug      升级一次，全部生效
```

**"通用版"的本质就是：一次开发，反复交付。** 每客户一套部署的话，你做 20 个客户就会累死。

技术上叫多租户（multi-tenant）：一个数据库，所有数据带 `tenant` 字段，中间件按访问的**域名**判断该给哪个客户看。

### 3️⃣ 后台：用现成的 Payload，不要自己写

这是省时间最多的一条。

| 方案 | 你要写什么 | 估计工期 | 评价 |
|---|---|---|---|
| **自研后台** | 登录、权限、表单、列表、媒体库、多语言、版本…全部自己写 | **+6～10 周** | 你卖的是网站，不是后台 |
| **Payload CMS**（推荐） | 只定义"有哪些字段"，后台自动生成 | **+0～1 周** | 内置多租户 + 多语言 + 权限 + 媒体库 |
| WordPress | 主题开发是另一套技术栈 | +3～4 周 | 和你的 React 投入完全不兼容 |
| Strapi / Directus | 能用，但要单独部署一个服务 | +2～3 周 | 多一层运维 |

**Payload 是这样的**：它就跑在你的 Next.js 项目里，你用 TypeScript 声明"产品有名字、图片、参数表"，它就自动给你一个完整的后台管理界面。已内置：

- ✅ **多租户**：单套代码服务多个客户域名，后台按租户隔离数据
- ✅ **多语言**：字段级翻译（同一个产品的中英西语名称）
- ✅ **权限**：超级管理员看全部，客户只能看自己的
- ✅ **媒体库**：上传、裁剪、缩略图
- ✅ **草稿 / 发布 / 版本回滚**
- ✅ **后台可白标**（挂你自己的 Logo，客户不知道底下是 Payload）

> 参考：[Payload 多租户能力](https://payloadcms.com/multi-tenancy)

## 一、产品定义：通用版外贸网站到底是什么

**一句话**：给外贸工厂的**多语言独立站**，带一个中文后台，老板自己能更新产品、看询盘。

**它和"定制网站"的区别**：

| | 定制网站 | 通用版外贸网站 |
|---|---|---|
| 交付方式 | 从零设计+开发 | 选模板 + 录内容 + 绑定域名 |
| 周期 | 1–3 个月 | 3–15 天 |
| 价格 | 3–10 万 | 年费几千起 |
| 改动 | 每次找开发 | 老板自己在后台改 |

**它的商业本质**：把"做网站"从**项目**变成**生产线**。

---

## 二、边界：第一版明确不做什么 ⭐

**这一节和功能清单一样重要。** 通用版最容易死在"什么都能做"。

| 不做 | 为什么 |
|---|---|
| ❌ 在线支付 / 购物车 | 外贸 B2B 是**询盘制**，不是零售电商。加了支付就变成另一个产品 |
| ❌ 库存 / 物流 / ERP 对接 | 客户有自己的 ERP，不归你管 |
| ❌ 自由拖拽装修器 | 第一版用"选区块 + 填内容"，不做自由拖拽。拖拽器是无底洞 |
| ❌ 多商家入驻平台 | 那是电商平台，要 EDI 许可证，另一个赛道 |
| ❌ 客户自助注册开通 | 第一版人工开通。你才刚开始，自助注册只会带来垃圾账号和配置错误 |
| ❌ 独立 App | 网站 + 手机自适应就够了 |
| ❌ 模板市场 | 第一版 1 套模板做精，能卖出去再加 |

> 记住一句话：**通用版的竞争力来自"交付快"，不是"功能多"。**

## 三、系统架构

```
                     客户各自的域名
        factory-a.com   |   factory-b.com   |   factory-c.com
                        ↓  （同一个入口）
        ┌───────────────────────────────────────────────┐
        │  Caddy —— 自动申请并续期 SSL 证书              │
        │  （每个客户域名自动 HTTPS，不用手工配）        │
        └───────────────────────────────────────────────┘
                              ↓
        ┌───────────────────────────────────────────────┐
        │  Next.js 15（一套代码，Docker）                │
        │  ├─ 中间件：按域名识别是哪个客户（租户）       │
        │  ├─ 前台：[locale]/...  给海外买家看           │
        │  └─ 后台：/admin  给老板用（Payload 生成）     │
        └───────────────────────────────────────────────┘
                    ↓                        ↓
        ┌────────────────────┐   ┌──────────────────────┐
        │  PostgreSQL        │   │  媒体存储            │
        │  所有租户数据       │   │  先本地磁盘，后 OSS  │
        └────────────────────┘   └──────────────────────┘
```

**部署方式**：一台海外云服务器（香港 / 新加坡）+ Docker Compose，一条命令起全套。

**为什么选 Postgres**：Payload 官方首选，多租户查询、JSON 字段、全文搜索都能用。

## 四、数据模型（这就是你后台的表单设计稿）

> 这一节同时回答了我上次说的"把 content 结构画成字段表"。

### 4.1 租户与账号

| 集合 | 字段 |
|---|---|
| **Tenants**（客户站点） | 站点名、标识 slug、**绑定域名（可多个）**、Logo、主色、联系方式（电话/邮箱/WhatsApp）、社交账号、默认语言、启用语言、模板、状态（试用/正常/到期）、到期日 |
| **Users**（后台账号） | 姓名、邮箱、密码、角色（超级管理员 / 客户管理员 / 客户编辑）、可访问的租户 |

### 4.2 内容

| 集合 | 字段 |
|---|---|
| **Categories**（产品分类） | 所属租户、上级分类、名称🌐、slug🌐、简介🌐、封面图、排序、是否显示 |
| **Products**（产品） | 所属租户、分类、名称🌐、slug🌐、一句话卖点🌐、详细介绍🌐（富文本）、**参数表🌐**（自定义键值对）、图集、PDF 图册、是否推荐、排序、状态（草稿/已发布） |
| **Pages**（页面） | 所属租户、标题🌐、slug、**区块组合**（见下）、SEO🌐、状态 |
| **Certificates**（认证资质） | 所属租户、证书名🌐、发证机构、证书图片、有效期 |
| **CaseStudies**（案例，P1） | 所属租户、客户名、行业、图片、描述🌐 |
| **Posts**（新闻资讯，P1） | 所属租户、标题🌐、正文🌐、封面、发布时间、SEO🌐 |
| **Media**（媒体库） | 所属租户、文件、文件名、**ALT 文字🌐** |

> 🌐 = 该字段支持多语言，每种语言填一份。

**页面区块（Blocks）** —— 决定首页和落地页长什么样：

| 区块 | 用途 |
|---|---|
| 首屏 Hero | 大图/视频 + 标题 + 两个按钮 |
| 产品网格 | 挑若干产品或分类展示 |
| 图文左右 | 工厂实力、产线、检测设备 |
| 认证资质 | 证书墙 |
| 数据条 | 厂房面积、员工数、年产量、出口国家数 |
| 常见问题 | FAQ（带结构化数据） |
| 询盘表单 | 可配置字段 |
| 富文本 | 自由内容 |
| CTA 条 | 底部行动号召 |

**老板在后台做的事就是**：选区块 → 填内容 → 排序 → 发布。不需要拖拽。

### 4.3 询盘（这是产品的核心价值）

| 集合 | 字段 |
|---|---|
| **Inquiries**（询盘） | 所属租户、姓名、邮箱、电话/WhatsApp、公司、国家、**来自哪个产品/页面**、留言、语言、来源渠道、状态（新 / 跟进中 / 已报价 / 成交 / 无效）、跟进负责人、跟进记录（多条）、创建时间 |
| **InquiryNotes** | 跟进人、时间、内容、下次联系时间 |

**为什么询盘管理要做得比"收邮件"好**：老板付年费的理由不是"我有个网站"，而是"**询盘一条都没丢，还知道谁在跟**"。

## 七、多语言方案

**URL 策略**：子目录（`你的域名.com/en/`、`/es/`），不用子域名。

- SEO 友好，权重集中在一个域名
- SSL 只需一张证书
- 实现简单

**第一版深度**：

| 层级 | 内容 | 第一版 |
|---|---|---|
| 界面语言 | 按钮、表单、提示语 | ✅ 做 |
| 内容多语言 | 产品名、描述、页面 | ✅ 做 |
| SEO 多语言 | hreflang、分语言 sitemap、分语言 TDK | ✅ 做 |
| AI 自动翻译 | 一键生成小语种初稿 | ❌ 放 P2 |

**默认只开英文**，客户要多语言就在后台勾选语种——这样第一版不用为小语种做额外工作。

> 阿拉伯语需要 RTL 排版支持，第一版可以先把 CSS 逻辑属性写好，别到后面返工。

## 八、SEO 方案（这是产品的**核心卖点**，不是附件）

客户为什么会续费？因为**有询盘**。询盘从哪来？SEO。

| 项 | 做法 |
|---|---|
| 每个页面独立 TDK | 后台可填，带默认值生成 |
| 语义化 HTML | H1/H2 层级、图片 ALT |
| sitemap.xml | 每个租户、每种语言各一份，自动生成 |
| robots.txt | 按环境生成 |
| hreflang | 多语言互指 |
| 结构化数据 | Organization / Product / FAQPage / BreadcrumbList |
| URL 结构 | `域名/语言/分类/产品` 静态化 |
| 性能 | 静态生成 + CDN + WebP + 懒加载 |
| 301 重定向 | 换 URL 时能配（P1） |

> **建议在产品里做一个「SEO 体检」**：告诉老板"你有 3 个产品没写描述、5 张图没填 ALT"。这比任何功能都更能证明你的价值。

## 九、技术选型

| 层 | 选择 | 理由 |
|---|---|---|
| 框架 | **Next.js 15**（App Router） | 和门户一致，组件与经验可复用 |
| 语言 | TypeScript | 一致 |
| 后台 + 数据层 | **Payload CMS 3** | 省 6–10 周后台开发 |
| 数据库 | **PostgreSQL** | Payload 首选 |
| 样式 | **Tailwind CSS v4** | 复用门户的设计系统 |
| 多语言 | Payload 字段级本地化 + next-intl | 内容和界面分开管 |
| 反向代理 / SSL | **Caddy** | 自动签发续期证书，每客户域名免手工配置 |
| 部署 | Docker Compose（海外 ECS） | 一条命令起全套，迁移方便 |
| 媒体 | 先本地磁盘 → 后对象存储 | 前期省事，后期好迁 |
| 邮件 | 阿里云邮件推送 / Resend | 新询盘通知 |
| 备份 | 每日 pg_dump + 媒体同步 | 客户数据丢了就是事故 |

## 十一、风险

| 风险 | 说明 | 应对 |
|---|---|---|
| **范围蔓延** | 通用版最大的死因 | 严格按第二节边界，新想法一律进 P2 |
| **模板不好看** | 功能全但丑，一样卖不出去 | 模板要专门投入设计时间，不能"开发顺手做" |
| 多租户架构 | 后期极难改 | M1 就定死，先跑通两个站点再往上加功能 |
| 数据越权 | 客户 A 看到客户 B 的数据 = 事故 | Payload 访问控制 + 每个集合强制租户过滤 + 写测试 |
| 客户域名 SSL 失败 | 客户会觉得"你网站做坏了" | Caddy 自动签发 + 后台显示证书状态 + 到期提醒 |
| 备份缺失 | 客户数据丢了就是事故 | 每日自动备份 + 定期恢复演练 |
| 老板不会用 | 后台再强，不会用等于没有 | 开通时录操作视频；后台做中文、做减法 |
