## 一、买服务器

### 买什么

| 项 | 选什么 | 说明 |
|---|---|---|
| **地域** | **香港** | 国内访问快（30–60ms）且**免备案**。这是门户（给国内客户看）和外贸站之间的最佳折中 |
| **类型** | **轻量应用服务器**优先 | 比 ECS 便宜、带宽大、控制台简单。做网站够用 |
| **配置** | **4核8G**（推荐）<br>2核4G + 2–4GB swap（省钱） | 要同时跑两个 Next.js + PostgreSQL + Caddy，**构建时最吃内存**，2核4G 容易 OOM |
| **系统盘** | 40GB SSD 起 | |
| **系统** | **Ubuntu 22.04 或 24.04 LTS** | Docker 支持最好。别选 CentOS 7（已停止维护） |
| **带宽/流量** | 看流量包，不看峰值带宽 | 香港节点带宽贵。**轻量服务器的"每月流量包"对网站更友好** |

> 价位参考：2核4G 大约每月几十到一百多元，4核8G 大约每月一百多到两百多元。
> **以实际活动价为准**，这类产品经常有促销。

### 在哪买

**推荐阿里云** —— 因为你的域名和 DNS 本来就在阿里云（`dns17/dns18.hichina.com`），少登一个控制台，解析也顺手。

腾讯云也可以，只是要单独管一个 DNS 控制台。

### ⚠️ 买的时候注意两点

1. **不要买"国内"节点**（北京/上海/杭州等）。国内节点**必须 ICP 备案**，而你现在没有公司主体，备案走不通。
2. **轻量服务器的防火墙在控制台配**，不在系统里。买完记得放行 **22 / 80 / 443** 三个端口。

## 二、买完立刻做四件事

### 1. 登录服务器

控制台里点"远程连接"，或用你本机终端：

```bash
ssh root@你的服务器IP
```

### 2. 装 Docker（复制粘贴即可）

```bash
# 官方一键脚本（Ubuntu / Debian）
curl -fsSL https://get.docker.com | sh

# 验证
docker --version
docker compose version
```

> 如果 `docker compose`（注意是空格，不是 `docker-compose`）报找不到，说明 compose 插件没装上，
> 按 `deploy/README.md` 里的说明补装。**以官方文档为准。**

### 3. 加 swap（只有买 2核4G 才需要）

```bash
# 建 4GB swap，防止构建时内存爆掉
fallocate -l 4G /swapfile
chmod 600 /swapfile
mkswap /swapfile
swapon /swapfile
echo '/swapfile none swap sw 0 0' >> /etc/fstab

# 确认
free -h
```

### 4. 安全三件事（别跳过）

```bash
# ① 改 SSH 端口（可选但建议），然后在控制台防火墙里同步放行新端口
# ② 关掉密码登录，改用密钥（阿里云控制台可以生成密钥对并绑定）
# ③ 检查防火墙：只放行 22 / 80 / 443
```

> 一台对公网开放、只有密码登录的服务器，被扫描尝试爆破是**每天都会发生**的事。

## 三、配 DNS（三条 A 记录）

在**阿里云域名控制台** → `shangbangbang.com` → 解析设置，加三条记录：

| 记录类型 | 主机记录 | 记录值 | 作用 |
|---|---|---|---|
| A | `@` | 你的服务器 IP | `shangbangbang.com` → **门户** |
| A | `www` | 你的服务器 IP | `www.shangbangbang.com` → **门户** |
| A | `*` | 你的服务器 IP | 所有子域名 → **外贸站**（客户站点） |

三个都填，TTL 用默认（10 分钟）即可。

> `*` 通配记录也会匹配 `www`，但显式记录优先，所以不用担心冲突。

### 验证生效

在你本机（不是服务器上）执行：

```bash
nslookup shangbangbang.com
nslookup ruitai-machinery.shangbangbang.com
```

两个都返回你的服务器 IP，就说明解析生效了。**解析没生效之前不要急着配 SSL**，证书会签失败，失败次数多了会被 CA 限流。

## 四、证书策略：第一版先别上通配符

这是个**需要你知道的取舍**：

| 方案 | 优点 | 代价 |
|---|---|---|
| **通配符证书**（`*.shangbangbang.com`） | 配一次，以后加客户不用动服务器 | **只能用 DNS 验证**，要自己编译带 DNS 插件的 Caddy 镜像 + 配阿里云 AccessKey |
| **逐个域名**（HTTP-01）✅ **第一版用这个** | 零 DNS 配置，Caddy 全自动 | 每加一个客户，要在 Caddyfile 里加一行，然后重启 Caddy |

**建议**：先用逐个域名把整套流程跑通（3 个演示站，就是 3 行），等真有客户了、觉得麻烦了，再上通配符。

Caddyfile 里两种写法都写了，切换时看注释即可。

## 五、你执行部署的步骤

完整步骤在 **`deploy/README.md`** 里（1000 多行，按顺序做就行）。核心就三步：

```bash
# ① 把代码传到服务器（git clone 或 scp，看你方便）
cd /opt && git clone <你的仓库地址> shangbangbang
cd shangbangbang/deploy

# ② 填环境变量：复制 .env.example 成 .env，按里面的中文注释逐项填
cp .env.example .env
nano .env

# ③ 起服务
docker compose up -d --build
```

### ⚠️ 第一次上线是**两段构建**，这是正常的

1. **第一次构建**：数据库是空的 → 只生成默认站点的页面 → **能起来**
2. **跑迁移 + 灌种子数据**：按 `deploy/README.md` 里的命令
3. **再构建一次**：这次才会为每个客户站点生成静态页面

**别忘了第 3 步**，否则新加的客户站点打不开。

## 六、我这边需要你反馈什么

部署过程中卡住了，把这三样贴给我，我能直接判断问题：

1. **你执行的命令**
2. **完整报错输出**（不是"报错了"三个字）
3. **相关容器的日志**：`docker compose logs --tail=100 <服务名>`

最常见的几类问题，`deploy/README.md` 第 9 章已经列了排查方法，包括：

- 证书签不下来
- 502 / 打不开
- **打开的是另一个客户的站点**（用 `curl -sI https://域名/ | grep x-site` 一眼定位）
- 门户和外贸站搞混了
