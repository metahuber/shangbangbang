# 邮件送达率配置清单（SPF / DKIM / DMARC）

> ⚠️ **这是外贸站最常见、代价最大、又最没人注意的坑。**
>
> 域名不配这三条 DNS 记录，你发出去的询盘通知、报价邮件、开发信会**大量进垃圾箱**。
> 而你在后台看到的永远是「发送成功」——**客户根本没收到，你还以为是没人回。**

---

## 一、先搞清楚：现在的情况

**目前你的外贸站还没有邮件功能。** 新询盘只写进容器日志（和可选的微信机器人通知）。

所以这份清单分两步：

| 步骤 | 什么时候做 |
|---|---|
| **① 先配好 DNS 记录** | 现在就能做，为以后发邮件铺路 |
| **② 再接邮件发送功能** | 等有了邮箱服务，再开发（约半天） |

**但有个更快的替代方案**：先用**企业微信机器人**收询盘通知（已支持，5 分钟配好），邮件功能往后放。

---

## 二、需要你先决定：用哪个邮件服务发信？

域名邮箱和「能程序化发信」是两件事。你需要的是后者：

| 服务 | 适合 | 备注 |
|---|---|---|
| **阿里云邮件推送（DirectMail）** | 国内主体、量大 | 你的 DNS 已经在阿里云，配置最顺 |
| **腾讯云 SES** | 同上 | |
| **Resend** | 开发者友好、海外送达好 | 需要海外主体或信用卡 |
| **QQ 企业邮箱 / 腾讯企业邮** | 量小、想省钱 | 有每日发信量限制，不适合批量 |
| Google Workspace | 海外送达最好 | 需要海外主体 |

**建议**：既然是**发给海外买家**，优先考虑送达率 → 阿里云 DirectMail 或 Resend。

> ⚠️ 具体选哪个、怎么开通，**以服务商的官方文档为准**。我不确定当前的价格和限制。

## 三、三条 DNS 记录

这三条都加在 **`shangbangbang.com`** 的 DNS 解析里（阿里云域名控制台）。

> ⚠️ 下面的值是**示例格式**。**实际值必须用你的邮件服务商给你的**——每家都不一样，填错等于没配。

### 1. SPF —— 声明「谁能代表这个域名发信」

| 项 | 值 |
|---|---|
| 记录类型 | `TXT` |
| 主机记录 | `@` |
| 记录值 | 由服务商提供，形如 `v=spf1 include:spf.example.com ~all` |

**注意**：
- 一个域名**只能有一条 SPF 记录**。如果已经有（比如腾讯企业邮），要把新的 `include:` 加进去，**不能再加一条**
- 结尾用 `~all`（软失败）而不是 `-all`（硬失败），留出容错空间

### 2. DKIM —— 给邮件签名，证明没被篡改

| 项 | 值 |
|---|---|
| 记录类型 | `TXT`（有些服务商给的是 `CNAME`） |
| 主机记录 | 由服务商提供，形如 `mail._domainkey` 或 `s1._domainkey` |
| 记录值 | 一段很长的公钥，服务商生成 |

**注意**：
- 这段值**很长**，复制时容易断行或漏字符 —— 建议复制完对比长度
- 有的服务商要你先在后台「开启 DKIM」才显示这一串

### 3. DMARC —— 告诉收件方「SPF/DKIM 没过时怎么办」

| 项 | 值 |
|---|---|
| 记录类型 | `TXT` |
| 主机记录 | `_dmarc` |
| 记录值 | `v=DMARC1; p=none; rua=mailto:你的邮箱@shangbangbang.com` |

**注意**：
- **先设 `p=none`**（只报告、不拦截）。观察一两周，确认正规邮件都通过之后，再考虑收紧成 `p=quarantine`
- **别一上来就设 `p=reject`** —— 会把你自己正常的邮件也拦掉

## 四、怎么验证配好了

### 方法一：在线检查（最简单）

发一封邮件到下面任意一个地址，拿回一份报告：

- 发到 `check-auth@verifier.port25.com`
- 或 `test@mail-tester.com`（网页上会给 0-10 分，**10 分算合格**）

### 方法二：命令行

```bash
# 看 SPF
dig +short TXT shangbangbang.com | grep spf

# 看 DMARC
dig +short TXT _dmarc.shangbangbang.com

# 看 DKIM（把 mail 换成服务商给的前缀）
dig +short TXT mail._domainkey.shangbangbang.com
```

### 方法三：Google Postmaster Tools

https://postmaster.google.com —— 能看到你的域名在 Gmail 眼里的信誉。**做外贸必备**（因为欧美买家大量用 Gmail）。

## 五、三个额外建议（很容易漏）

### 1. 用子域名发信，别用根域名

比如用 `mail.shangbangbang.com` 或 `noreply.shangbangbang.com` 发**系统通知**。

**为什么**：万一批量发信把信誉搞坏了，只影响子域名，**不会连累你人工收发的根域名邮箱**。

### 2. 配 `reply-to`，别用 `no-reply`

客户回了邮件没人看，等于没发。**要么用能收信的地址，要么配上 `reply-to`。**

### 3. 新域名刚上线，别马上群发

新域名没有发信历史，**一上来群发 500 封 = 直接进垃圾箱**。

正确做法：**先少量、持续地发**（每天几封到几十封），让信誉慢慢长起来。这个过程通常要 **2–4 周**。

## 六、每个客户站点的邮件怎么办？

你的产品是多租户，客户有自己的域名。理论上：

| 方案 | 说明 | 复杂度 |
|---|---|---|
| **A. 先用你的域名发**（推荐起步） | 用 `shangbangbang.com` 发，`reply-to` 设成客户的邮箱。客户收到通知就行 | 低 |
| **B. 每个客户配自己的域名** | 客户在自己 DNS 里加三条记录。**每开一个客户就要配一次**，还要等生效 | 高 |

**建议先用 A。** 等客户多了、有客户明确要求「询盘通知要显示我们公司的发件人」时，再上 B。

## 七、什么时候做这件事

| 时间 | 做什么 |
|---|---|
| **现在** | 先配企业微信机器人收询盘通知（5 分钟，立刻可用） |
| **有邮箱服务后** | 配 SPF / DKIM / DMARC 三条记录 + 验证 |
| **接着** | 开发邮件通知功能（给客户自动回复、给业务员提醒） |
| **上线 2–4 周后** | 信誉稳定了，再考虑开发信 / EDM |

> ⚠️ **不要跳过验证那一步。** 配了不验证，等于没配。
